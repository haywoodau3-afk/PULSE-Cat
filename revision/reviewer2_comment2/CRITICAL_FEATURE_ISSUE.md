# Critical feature issue: prior manuscript results are provisional

A source-code audit found that the archived pose-feature pipeline used atom index 0 as the nitrene nitrogen even when the nitrene was elsewhere in the RDKit molecule ordering. For 1ah, atom 0 is carbon; direct XYZ verification gives mean nitrene-N-to-reactive-C distance 3.5815 Å, while the archived value is 2.5386 Å. Recalculating 1ah changes 172 of 248 Stage 2p fields. Twelve of 38 active Fe(P7)Cl records and 14 of 26 active Fe(CMC-Por)Cl aryl records have the same index-order hazard; 30 of 50 CMC records show changed Stage 2p fields after regeneration. This includes several low-ee examples and fixed-audit records.

The code has been corrected locally in `scripts/stage2_pose_interaction.py`, `scripts/stage2p_representation.py` and `scripts/stage3a_reference_features.py`; targeted regression tests pass and broader rebuilding is underway. Corrected Stage 2p features for the relevant P7 and CMC populations have been generated. The previous manuscript and supporting-information DOCX, prior reviewer responses, and the staged companion package still refer to historical results computed using uncorrected features. Do not submit them or claim those findings are validated until all affected analyses are rebuilt, independently verified and the conclusions/documents/release package updated. The previous commenter closeouts need to be revisited to the extent they depend on affected feature sets.

Current work and validation details are in `analysis_plan.md`, `results/`, `validation_report.json`, and the local code/tests. Source ee measurements and 2D chemical identities are not changed by this feature-generation error; their model predictions may change. The current example figure uses corrected pose predictions, but it and all related documents remain provisional until the corrected workflows have been independently verified and reconciled.
